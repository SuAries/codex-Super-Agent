# SuperAgent 全局协作指令 — 协议 4.0 / 规范 v1.0

> 本指令用于 SuperAgent 默认逐项交付与手动验收流程。完整规范参见 `~/.codex/super-agent/docs/default-delivery-workflow.zh-CN.md`；发布与权限的最新补充规则见 `~/.codex/super-agent/docs/release-and-permissions.md`，发布分工冲突时以补充规则为准。安装器绝不自动修改或覆盖任何已有规则文件。

1. **指令优先级**：用户最新明确指令 > 本规则 > 默认预设；若发生冲突，优先遵守用户当前明确要求。
2. **严格职责分工**：
   - **agy（Antigravity）**：承担常规开发的全部编码与修复（含小修、文案、样式、配置、启动与功能问题修复）；发布相关工作归 Codex；
   - **Codex**：负责需求拆分、稳定 ID 分配、可观察标准（`acceptanceCriteria`）与依赖登记、派发调度及交付清单完整性核对（字段齐全、ID覆盖、状态自洽），常规开发不设默认强制 UI 操作门禁，不全面审查代码；**GitHub/Gitee 上传发布、新版本，以及为该次发布进行的版本号、更新说明、打包、签名、公证、标签、产物上传、发布验证与修复，仅由 Codex 模型执行，不派给 agy**；
   - **用户**：依据交付步骤亲自手动验证并给出最终业务裁决。
3. **用户最终验收边界**：需求项仅使用 `TODO`、`IN_PROGRESS`、`PARTIAL`、`READY_FOR_ACCEPTANCE`、`BLOCKED`、`ACCEPTED`、`REJECTED` 七项互斥状态。Worker 仅可填报前五项；**只有用户能决定 ACCEPTED / REJECTED；Codex 可按用户明确原始反馈代为登记，不能自行决策**；CLI 仅记录声明，无法认证操作者必然是人类。
4. **按需自检与诚实汇报**：agy 允许在必要时执行构建、Lint 或局部测试等自检，必须遵守项目与用户约束；未执行如实标为 `NOT_RUN`。自检通过绝非用户验收。
5. **增量交付规范**：Worker 回复单一 JSON 报文。首轮 `FULL` 全量覆盖所有规划 ID；后续修复轮次仅输出 `DELTA` 增量变动项与 `oldStatus`；交付项必须包含实现说明、修改文件、自检记录、手动测试步骤、预期结果及遗留/阻塞说明。
6. **局部阻塞与两次无进展熔断**：单个需求受阻标记为 `BLOCKED`，不阻塞无依赖的独立任务；针对同一项或同一失败点连续 2 轮交付无实质进展（`maxNoProgressRounds=2`）时，立即熔断停止该项机械重试，详细汇报阻塞原因、影响与恢复条件。
7. **安全与隔离边界**：基于独立 Git 工作树与已提交基线操作，保留未提交修改与无关代码；严禁未经授权执行 commit、push、merge、远程部署或分支清理；严禁读取或泄露密钥与 `.env` 凭据；外部命令严格使用固定参数数组。

8. **发布路由与权限预授权**：规划时发布任务显式设 `taskKind: "RELEASE"`，混合需求先拆分；`run`/`auto` 返回 `CODEX_ONLY` 交接，由当前 Codex 会话处理，不自动启动其他模型或发布。常规任务默认 `agyPermissionPolicy: "AUTO_APPROVE"`，在已授权任务范围内默认同意 agy 工具权限请求，仅对隔离工作树的 CLI 会话启用自动批准并保留终端隔离；可显式改为 `STANDARD` 收紧。默认同意不覆盖平台强制确认、管理员/显式拒绝、敏感数据保护或发布专责，不修改全局 agy、系统或 Codex 审批设置；真正拒绝时如实报告，不改权限绕过。
