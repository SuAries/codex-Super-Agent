# Codex 启动/打开验证规范（历史兼容保留）

> [!NOTE]
> 在 SuperAgent 0.7.0（协议 4.0）中，全局默认流程为[默认逐项交付与手动验收规范](default-delivery-workflow.zh-CN.md)（规范 v1.0）。
> 本规范（`verify`）作为历史兼容支持保留，用于旧的 `CODEX_STARTUP_CHECK` 任务。旧的 `STARTUP_ONLY` / `OPENED` 记录继续保持其原意，不可冒充为新协议的用户 `ACCEPTED` 或功能通过。

## 通过标准

全局采用严格分工模式：所有代码修改（包括业务开发、一行小修、样式和文案、小配置调整及启动报错修复）均严格由 Antigravity 编码完成，Codex 无直接编码例外，Codex 不替代编码。Codex 只做实际打开确认：测试 App 窗口正常出现，或测试网页在浏览器正常加载，启动阶段没有报错。之后保留窗口/网页和必要开发服务，交给用户自行测试。

这不表示业务功能正确、所有代码正确或自动化测试通过。不默认进行全仓源码审查、安全扫描、单元/集成/E2E 测试、Lint、typecheck、CI 或业务操作遍历。

## 操作顺序

1. 从启动交接信息获取正确命令、URL 或 App 路径；必要时只读入口/启动配置。
2. 执行真正打开目标所需的开发服务或启动构建；用户明确禁止的步骤不执行。
3. 在实际 App/浏览器界面观察能否正常打开，查看启动阶段可见错误。Codex 严禁直接修改代码修复任何启动问题或配置缺陷。
4. 正常打开记录 OPENED，交给用户测试；实际启动失败才记录 STARTUP_FAILED 并反馈错误给原 Antigravity Worker 返工修复。缺少目标、观察能力或权限时记录 NOT_VERIFIED，不伪造通过。

HTTP 200、后台进程存在、构建成功、Worker SUCCESS 或日志“ready”不能替代实际打开。无需为了“验证”去检查每一项业务行为。

## CLI 记录

verify 只保存当前 Codex 已经观察到的事实，不自行打开目标，也不调用源码 Reviewer。

```bash
node ~/.codex/super-agent/cli.mjs verify --id <id> --kind web --target http://localhost:5173 --result opened --evidence "已实际打开首页，未观察到启动报错"
node ~/.codex/super-agent/cli.mjs verify --id <id> --kind app --target /absolute/Test.app --result failed --error "实际启动错误" --evidence "启动时实际观察到的情况"
node ~/.codex/super-agent/cli.mjs verify --id <id> --result blocked --evidence "未能实际打开的原因"
```

必须根据真实观察填写，不可复制成功例句冒充已打开。失败可重复 --error 记录启动错误。也可 `verify --id <id> --file startup-check.json`。

| 报告字段 | 记录内容 |
|---|---|
| taskId / workerAttempt / worktreePath | 当前任务、最近编码次数和对应工作树 |
| kind | web / app；无法确定时为 unknown |
| target | 实际 URL/App 路径；未确定时为 null |
| outcome | OPENED / STARTUP_FAILED / NOT_VERIFIED |
| errors | 启动阶段真实错误字符串数组，正常打开时为空 |
| evidence | 实际看到的窗口/网页和启动情况，可附截图或日志位置 |
| observedAt | 本次实际观察时间，规范 ISO 格式 |
| verificationScope | 固定 STARTUP_ONLY |
| checkedBy | 固定 CODEX_CURRENT_SESSION |

OPENED 只在正常打开且无启动错误时使用，任务进入 READY_FOR_USER_TEST。STARTUP_FAILED 进入 CHANGES_REQUESTED，只携真实启动错误返工，默认最多两轮；NOT_VERIFIED 进入 BLOCKED，明确没有完成打开。

记录只说明观察当时的启动状态，不长期监控服务，也不生成源码 SATISFIED 覆盖矩阵。再次编码后要重新打开，不能用上轮观察替代。启动生成的正常缓存和构建输出不作为源码审查或启动失败依据。

## 简洁交付

说明打开的 App 名称/路径或测试 URL、是否正常打开、是否观察到启动报错，并明确“接下来由你自行测试”。未实际打开就说“未验证”和具体原因。
